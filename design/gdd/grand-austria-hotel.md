# 奥地利大饭店 (Grand Austria Hotel) — 游戏设计文档

## 1. Overview

《奥地利大饭店》是一款 2-4 人回合制策略桌游的数字实现。玩家扮演 20 世纪初维也纳的旅店老板，通过掷骰选取行动、邀请宾客、准备客房、满足宾客需求获取分数，同时管理员工卡牌和皇室关系。游戏共进行 7 轮，第 3/5/7 轮结束时进行皇室计分，第 7 轮结束后进行最终计分，最高分玩家获胜。

本项目为纯前端数字实现，使用 TypeScript + React + Zustand 构建，支持本地热座多人模式。

---

## 2. Player Fantasy

玩家将体验经营一家维也纳大饭店的紧张与成就感。每一轮掷骰后的决策都充满策略深度：是优先邀请高价值宾客、扩张客房、还是投资皇室关系？员工卡牌的组合提供了多样化的成长路线，政治卡则引导玩家的中期目标。玩家需要平衡短期收益（满足宾客）与长期布局（客房区完成奖励、皇室计分），感受从一个小旅店逐渐发展为豪华大饭店的成长历程。

## 3. 详细规则

### 3.1 游戏流程

#### 开局设置

在进行 7 轮游戏之前，先执行开局设置：

1. **游戏版图设置**：放置游戏版图、行动版图、分类餐饮标记、洗匀宾客卡和员工卡
2. **宾客区**：从宾客牌库顶抽 5 张正面朝上放在 5 个宾客区域
3. **政治卡**：从 A/B/C 三组中各抽 1 张政治卡放到版图指定区域
4. **皇室板块**：从 A/B/C 三组中各抽 1 个皇室板块放到版图指定区域
5. **玩家设置**：每位玩家拿取酒店版图、6 个对应颜色木制圆片、1 张帮助卡
6. **资金**：起始资金 10 克朗
7. **厨房**：每种餐饮（咖啡、红酒、蛋糕、馅饼）各 1 个放入厨房
8. **员工卡**：每位玩家抽 6 张员工卡（隐藏信息）
9. **准备客房**：每位玩家准备最多 3 个客房（必须从版图左下角开始放置，需相邻，按费用支付）
10. **免费邀请宾客**：由起始玩家开始，按**逆时针**顺序，每位玩家从游戏图板上**免费**邀请 1 位宾客到自己的咖啡厅。每有一位玩家挑选后，将剩余宾客右移，从牌库翻开新宾客填补左边空位
11. **回合顺位**：起始玩家拿 No1 板块，顺时针依次分发 No2/No3/No4

#### 每轮流程

游戏共 7 轮，每轮流程：

1. **掷骰阶段**：起始玩家掷所有骰子，按点数分类放到行动区
2. **行动阶段**：按回合顺位依次行动
   - 可选：从游戏图板邀请一位宾客（需支付费用，最多容纳 3 位）
   - 必选：拿取一个行动区骰子，执行对应点数行动
   - 可选：执行额外行动（不限次数，但 `add_die` 每回合限一次）
3. **轮结束**：翻回员工卡、传递顺位板块、轮次标记前进
4. **第 3/5/7 轮结束**：先进行皇室计分，再进入下一轮

### 3.2 骰子行动（6 种）

| 点数 | 行动名称 | 说明 |
|------|----------|------|
| 1 | 获取面点 | 每骰拿 1 个馅饼或蛋糕，蛋糕数 ≤ 馅饼数 |
| 2 | 获取饮品 | 每骰拿 1 个红酒或咖啡，咖啡数 ≤ 红酒数 |
| 3 | 准备客房 | 每骰准备 1 个客房（需相邻、同色、付费） |
| 4 | 皇室/金钱 | 每骰可分配推进皇室轨或金钱轨，可拆分 |
| 5 | 雇佣员工 | 每骰减 1 元雇佣费用 |
| 6 | 万能行动 | 支付 1 元，使用 6 区骰子数执行其他 1-5 行动之一 |

### 3.3 额外行动

回合中可执行任意次（`add_die` 除外）：

- **add_die**（每回合限一次）：支付 1 元，让某行动区视为多 1 骰
- **move_kitchen**：支付 1 元，从厨房移最多 3 个餐饮到宾客需求区
- **place_politics**：满足条件时放置政治标记
- **use_staff_ability**：使用"每轮一次"员工能力
- **move_guest**：满足需求的宾客入住对应颜色空房，获得分数和奖励

### 3.4 宾客系统

- 共 56 张宾客卡，4 种颜色：蓝（贵族）、黄（艺术家）、红（市民）、绿（观光客）
- 宾客卡包含：餐点需求、分数、入住奖励
- 从图板邀请需支付费用（印在图板上），邀请后补充新卡
- 完成需求后可入住对应颜色客房（绿色可住任意颜色）
- 入住获得：卡面分数 + 入住奖励 + 可能的满房奖励

### 3.5 客房系统

- 3 种颜色：蓝、黄、红，每种 28 个
- 每个玩家版图 10 个区域/群组
- 准备客房需：相邻、同色、支付费用（按行付费）
- 入住后翻转客房板块
- 群组全部入住 → 触发满房奖励（黄 = 皇室轨、蓝 = 分数、红 = 金钱）

### 3.6 员工卡系统

- 共 48 张员工卡，4 种使用时机：
  - **one_time**（一次性）：打出时立即生效
  - **once_per_round**（每轮一次）：每轮可使用一次，使用后翻面
  - **permanent**（永久）：持续生效的被动能力
  - **end_of_game**（游戏结束）：终局额外计分
- 雇佣费用在行动 5 执行，每骰减 1 元

### 3.7 皇室计分系统

- 皇室轨共 13 格，超过 13 每格得 1 分
- 第 3 轮结束：后退 3 格；第 5 轮：后退 5 格；第 7 轮：后退 7 格
- 后退后位置 ≥ 3（黄色区）：获得皇室板块奖励
- 后退后位置 = 0：受到皇室板块惩罚
- 后退后位置 1-2：无奖惩

### 3.8 政治卡系统

- 共 12 张，每局使用 3 张（A/B/C 各 1）
- 条件满足时可将标记放在最高开放位置并获得分数
- 每位玩家每张卡只能放 1 个标记

### 3.9 跳过回合

- 可主动跳过，等其他玩家完成 2 次行动后
- 轮到的玩家收集剩余骰子、移除 1 颗、重骰后继续

### 3.10 游戏结束 & 终局计分

1. 员工卡终局分数
2. 已入住客房分数（第 1 排 ×1、第 2 排 ×2、第 3 排 ×3、第 4 排 ×4）
3. 每 1 元 = 1 分，厨房每剩余餐饮 = 1 分
4. 咖啡厅每剩余 1 位宾客 = -5 分
5. 政治标记分数
6. 平手：比较剩余餐饮 + 金钱

## 4. 公式

### 4.1 分数计算

```
总分数 = 宾客卡面分数 + 入住奖励分数 + 满房奖励分数 + 皇室计分 + 
         政治卡分数 + 员工卡终局分数 + 客房分数 + 金钱/餐饮 - 未入住宾客惩罚

客房分数 = row1_count × 1 + row2_count × 2 + row3_count × 3 + row4_count × 4
宾客惩罚 = unserved_guest_count × 5
金钱分数 = money
餐饮分数 = kitchen_food + kitchen_wine + kitchen_coffee + kitchen_cake
```

### 4.2 员工费用

```
实际费用 = max(0, 员工卡费用 - 行动5骰子数 - 折扣效果)
```

### 4.3 皇室后退

```
Round 3: new_position = max(0, current_position - 3)
Round 5: new_position = max(0, current_position - 5)
Round 7: new_position = max(0, current_position - 7)
```

### 4.4 厨房取用

```
单次最多取出 3 个餐饮
每次费用 = 1 元（除非有 free_serve_guest 能力）
```

## 5. 边界情况

| # | 场景 | 处理方式 |
|---|------|---------|
| 1 | 皇室轨超过 13 | 停止前进，每超过 1 格得 1 分 |
| 2 | 厨房无足够餐饮 | 只能取出已有的数量 |
| 3 | 咖啡厅已满（3 位） | 不能邀请新宾客 |
| 4 | 无对应颜色空房 | 宾客不能入住，留在咖啡厅 |
| 5 | 员工费用减到 0 以下 | 不退款，按 0 处理 |
| 6 | 跳过回合时行动区无骰子 | 回合立即结束 |
| 7 | 牌库耗尽 | 不洗牌，无卡可抽 |
| 8 | 政治卡条件同一回合多玩家满足 | 按回合顺位依次判定 |
| 9 | 满房奖励与入住同时触发 | 先获得入住分数/奖励，再触发满房奖励 |
| 10 | 多人平手 | 比较剩余餐饮 + 金钱总数 |

## 7. 调优旋钮

| 参数 | 默认值 | 可调范围 | 影响 |
|------|--------|---------|------|
| 起始资金 | 10 元 | 8-15 | 早期扩张速度 |
| 厨房容量 | 每种食材各 1（起始） | — | 餐饮获取策略 |
| 咖啡厅容量 | 3 位 | 2-4 | 宾客管理难度 |
| 皇室后退步数 | 3/5/7 | 可调整 | 皇室策略权重 |
| 骰子数量 | 10/12/14（2/3/4人） | — | 行动频率 |
| 政治卡分数 | 15/10/5（第1/2/3名） | 可调整 | 政治卡竞争强度 |
| 终局客房分数 | 1/2/3/4（排） | 可调整 | 客房扩张价值 |
| 未入住宾客扣分 | 5 分/位 | 3-7 | 宾客管理惩罚力度 |
